# 从逐位置包装到异构组合：`*` 参数包教程

[English](tutorial.md) | 简体中文

这份教程对应本目录的独立模型 v2；其参数包语义已经接入 **batch-impl 0.10.0 开发版（未发布）**。代码块展示目标类型表达式与生成的 Rust 类型，不是完整宏程序；实际方法体仍由 batch-impl 的现有机制负责。

模型可以运行；教程中带验算标记的例子都有固定预期结果。运行统一入口后，完整的普通 Rust 验证程序生成在 `target/pack-model/generated_examples.rs`，它独立验证生成目标及参数关系；公开宏另由仓库的 Rust 回归套件验证。

先记一句话：**普通构造器整包取参；带星的构造器逐项工作；每次只打开右包当前这一层。**

## 1. 从一包参数开始

`*(u8,u16)` 是一包两个成员。把它交给普通 `Pair`，两个成员成为两个泛型实参：

<!-- example: args -->
```text
Pair *(u8,u16)
```
<!-- output: args -->
```rust
Pair<u8,u16>
```

如果左边也加星，意思就变成“让里面的构造器分别处理右包中的每一项”：

<!-- example: map -->
```text
(*Vec *(u8,u16),)
```
<!-- output: map -->
```rust
(Vec<u8>,Vec<u16>)
```

这里有三个不同的东西：`Vec` 是普通构造器；`*Vec` 是装着这个构造器的包；最外面的 `(...,)` 是最后承接结果的普通元组。包是中间结构，不是额外的 Rust 类型，也不是要用户命名的变量。

包可以包含普通元组，而普通元组仍算一个成员。只有带星的包才会在最终收纳时摊开。

## 2. 每个位置生成独立参数，再分别包装

假设你维护一个列式容器：每列的元素类型可能不同，但每列都用 `Vec` 保存。目标类型是 `(Vec<T0>, Vec<T1>, Vec<T2>)`。

`().3` 生成一个含三个 fresh 参数的普通元组；`*().3` 生成含三个参数的包。把后者交给 `*Vec`：

<!-- example: vec-fixed -->
```text
(*Vec *().3,)
```
<!-- output: vec-fixed -->
```rust
(Vec<T0>,Vec<T1>,Vec<T2>)
```

这适合为不同字段类型组成的列缓存生成布局标记、注册接口等一族 impl。`T0`、`T1`、`T2` 是三个独立的泛型参数；用户将来仍然可以把其中几个实参选成相同的 Rust 类型。

希望支持一列到三列，只把长度改成范围：

<!-- example: vec-range -->
```text
(*Vec *().1..=3,)
```
<!-- output: vec-range -->
```rust
(Vec<T0>,)
(Vec<T0>,Vec<T1>)
(Vec<T0>,Vec<T1>,Vec<T2>)
```

这是三个不同目标，每个目标各自声明自己的参数。`..` 不包含右端点，`..=` 包含右端点。这里的参数名只为阅读方便；模型使用带生成器身份的名字，关系与此相同。

## 3. 同一位置内部复用参数

现在每个字段还要保存一份当前值，于是需要 `Pair<T, Vec<T>>`。同一个位置的两处 `T` 必须相同，位置之间则独立。

先看小步骤：`*(self,Vec) T` 会构造一包 `T` 和 `Vec<T>`。其中 `self` 是 DSL 的恒等前缀，收到什么就返回什么；它不是 Rust 的方法接收者，也不是 `@Self`。

把这一步用于每个 fresh 参数，再让 `Pair` 接收每一包：

<!-- example: pair-fixed -->
```text
(*Pair (*(self,Vec) *().3),)
```
<!-- output: pair-fixed -->
```rust
(Pair<T0,Vec<T0>>,Pair<T1,Vec<T1>>,Pair<T2,Vec<T2>>)
```

按括号从里向外读：先生成三个参数；分别构造“参数本身 + Vec”；再把每一包交给 `Pair`；最后装进外层元组。

**右包中的每一行是一次完整输入。** 这里的一行自身也是包，所以 `Pair` 得到的是 `T0、Vec<T0>` 这两个实参，不会被迫分别生成 `Pair<T0>` 和 `Pair<Vec<T0>>`。

熟悉以后，可以利用点号右结合，缩短嵌套括号。长度族的写法是：

<!-- example: pair-range -->
```text
(*Pair.*(self,Vec).*().1..=3,)
```
<!-- output: pair-range -->
```rust
(Pair<T0,Vec<T0>>,)
(Pair<T0,Vec<T0>>,Pair<T1,Vec<T1>>)
(Pair<T0,Vec<T0>>,Pair<T1,Vec<T1>>,Pair<T2,Vec<T2>>)
```

空格仍然左结合，点号仍然右结合。刚接触时，优先使用上一例的空格加括号写法。

## 4. 每个位置保留一个普通元组

不使用自定义 `Pair`，直接需要 `(T, Vec<T>)`，就把 `Pair` 换成普通元组构造器 `()`。

不过，`*()` 是空包；“包装着一个 `()` 构造器的包”要写 `*((),)`：

<!-- example: tuple-fixed -->
```text
(*((),) (*(self,Vec) *().3),)
```
<!-- output: tuple-fixed -->
```rust
((T0,Vec<T0>),(T1,Vec<T1>),(T2,Vec<T2>))
```

这是“当前值 + 历史记录”一类异构字段状态的直接表达。每一行已经构造成普通元组，所以最终拼接外层包时，行不会再被拆开。

省掉构造内层元组的步骤，就只会得到平坦成员：

<!-- example: flat-members -->
```text
(*(self,Vec) *().2,)
```
<!-- output: flat-members -->
```rust
(T0,Vec<T0>,T1,Vec<T1>)
```

这里不需要双星。是否保留结构，取决于有没有明确构造普通元组。

**学到这里已经覆盖最初的三个常见目标：逐位置包装、同位置复用参数、保留每个位置的内部结构。** 后面是需要时再看的组合应用。

## 5. 两个常用变体

### 每种字段配两个缓冲区

把 `self,Vec` 换成 `Vec,Vec`，得到同一元素类型的两个容器，可用于前后缓冲、读写缓冲等类型布局：

<!-- example: double-buffer -->
```text
(*((),) (*(Vec,Vec) *().2),)
```
<!-- output: double-buffer -->
```rust
((Vec<T0>,Vec<T0>),(Vec<T1>,Vec<T1>))
```

生成的是布局目标。交换缓冲区、同步状态等业务行为仍需方法体实现。

### 每个位置连续包装

先把每个参数放进 `Box`，再把每个结果放进 `Vec`：

<!-- example: nested-wrap -->
```text
(*Vec (*Box *().2),)
```
<!-- output: nested-wrap -->
```rust
(Vec<Box<T0>>,Vec<Box<T1>>)
```

括号不能省成 `*Vec *Box *().2`。空格左结合，后者先做 `Vec Box`，后续会继续追加参数，而不是回到 `Box` 里面填参。

同样，`Vec.Box` 是已经构造的 `Vec<Box>`；把它放进一个包，不会自动变成带隐式参数洞的函数。参数包没有引入任意模板或 lambda。

## 6. 两组参数组合，并决定是否保留行

例如一组输入类型与一组输出类型分别有两个和三个成员，`Map<T,U>` 表示某种两端类型关系。这里共有五个参数，需要六种配对。

<!-- example: flat-grid -->
```text
(*Map *().2 *().3,)
```
<!-- output: flat-grid -->
```rust
(Map<T0,U0>,Map<T1,U0>,Map<T0,U1>,Map<T1,U1>,Map<T0,U2>,Map<T1,U2>)
```

右边的维度在外：先固定 `U0`，遍历 `T0/T1`，再处理 `U1`、`U2`。这是笛卡尔组合，不是 zip；两个维度长度不必相同。

内部行其实还在。像上一节一样，用普通元组构造器接住每行，就得到二维布局：

<!-- example: row-grid -->
```text
(*((),) (*Map *().2 *().3),)
```
<!-- output: row-grid -->
```rust
((Map<T0,U0>,Map<T1,U0>),(Map<T0,U1>,Map<T1,U1>),(Map<T0,U2>,Map<T1,U2>))
```

这适合保留输入/输出关系矩阵的两条维度。将两个长度分别换成 `1..=2` 和 `1..=3`，本轮生成的六个嵌套目标可以为同一个 trait 实现，已经通过 rustc 验证。

对应的**扁平长度族会冲突**：`1×2` 与 `2×1` 的泛型模式可能覆盖同一个具体类型，rustc 报 E0119。保留行解决了这个例子的维度混同，但不是一般的 impl 不重叠保证。

## 7. 候选列表控制“选择”，包控制“一起构造”

这三个需求不同：

| 需求 | 写法 | 结果数量 |
|---|---|---:|
| 整组统一使用 Vec 或 Box | `([*Vec,*Box] *().2,)` | 2 个目标 |
| 每个位置分别选择 Vec 或 Box | `(*([Vec,Box],) *().2,)` | 4 个目标 |
| 每个位置同时保留 Vec 和 Box | `(*(Vec,Box) *().2,)` | 1 个目标，4 个成员 |

第二行的完整输出是：

<!-- example: local-choice -->
```text
(*([Vec,Box],) *().2,)
```
<!-- output: local-choice -->
```rust
(Vec<T0>,Vec<T1>)
(Vec<T0>,Box<T1>)
(Box<T0>,Vec<T1>)
(Box<T0>,Box<T1>)
```

候选也能选择不同长度的整包：

<!-- example: branch-packs -->
```text
(*Vec [*(u8,),*(u16,u32)],)
```
<!-- output: branch-packs -->
```rust
(Vec<u8>,)
(Vec<u16>,Vec<u32>)
```

不要把候选列表理解成“一个先选定、之后处处共享的变量”。当前应用位置外露的候选先分派；藏在普通类型内部的候选表达式被复制后，仍可独立选择。比如 `([A,B],).2` 保持四种组合，不会收缩成只有 `(A,A)` 和 `(B,B)`。

## 8. 最容易误读的几个边界

**整个元组与每个成员不同。** 不给生成器结果加星，可以把整个元组当作一个输入：

<!-- example: whole-tuple -->
```text
Pair.*(self,Vec).().2
```
<!-- output: whole-tuple -->
```rust
Pair<(T0,T1),Vec<(T0,T1)>>
```

**星放在范围外面会收集整个族。** 下面得到一个目标，成员是两个“包装整个元组”的 Vec：

<!-- example: collect-family -->
```text
(*Vec *(().1..=2),)
```
<!-- output: collect-family -->
```rust
(Vec<(T0,)>,Vec<(U0,U1)>)
```

**星不会把单槽变成多槽。** 泛型实参表、元组字段表、函数参数表可以接收多项；引用目标、指针目标、切片元素、函数返回类型只能接收一项。`&*(u8,)` 可以物化成 `&u8`，`&*(u8,u16)` 应明确报错。

**逗号明确容器。** 对本教程的普通类型和包表达式，`(X)` 是透明分组，`(X,)` 才是一元组；`[X]` 是切片，`[X,]` 才是单项候选列表。`*const`、`*mut` 始终先按 Rust 原始指针识别。现有 `@` 位置引用等元语法的特殊分组契约未被本轮重定义，独立模型尚未覆盖这些语法。

**空包不是装着空元组的包。** `*()` 没有成员；`*((),)` 有一个普通元组构造器；`*(*(),)` 则有一行空参数包。后两者也不同。

**能构造类型不等于能生成合法 impl。** 例如 `(*Map *().2 *().0,)` 的目标形状是 `()`，但被携带出来的两个泛型不受约束，实际得到 E0207。模型保留这个错误，没有偷偷删除参数。重复目标也不自动去重。

## 9. 从旧语义迁移时，要明确接受哪些变化

| 旧行为/写法 | 0.10.0 参数包语义 | 保留原意的写法 |
|---|---|---|
| `*(F,G) T` 追加 T | 改为分别构造 F、G | `*((F,G) T)` |
| `*(...)` 与 `*[...]` 分别记住元组/列表来源 | 统一成参数包 | 用普通元组或显式候选表达所需区别 |
| `*[F,G].2` 对两个构造器分别施加数字 | 包按元组规则求幂 | `*(F.2,G.2)` |
| `(*(A,B))` 可隐式成为外层元组 | 普通分组透明 | `(*(A,B),)` |
| `[*(A,B)]` 的 lone-splat 特例可表示列表 | 无逗号仍按切片 | `[*(A,B),]` |
| 包内部的普通候选也被自动摊成同时保留的成员 | 候选继续表示选择 | 对需要收集的那层候选显式加星 |

这是 0.10.0 的破坏性语义变更，不能描述成完全兼容的语法糖。普通元组求幂仍保持原来的直接槽位规则；`(*(A,B),).2` 仍是一个 `(A,B,A,B)` 目标。

## 10. 运行模型与查看验证

在仓库根目录运行：

```text
python tests/pack_model/run.py
python tests/pack_model/run.py --eval "(*((),) (*(self,Vec) *().3),)"
```

`syntax.py` 是严格的子集解析器：不支持的输入应报错，不会静默丢字符。它没有覆盖公开宏的所有语法；例如完整声明块、where、绑定与属性，以及部分已有前缀 apply，没有在这个小解析器中实现。模型拒绝这些内容不等于公开宏禁止它们。

规则的精确定义、修正记录和生产验证边界见 [contract.zh-CN.md](contract.zh-CN.md)。运行后，验证统计写入 `target/pack-model/validation.json` 与 `target/pack-model/exhaustive_results.json`。有限检查不能证明任何输入都无缺陷；当前结论限定为：本轮已关闭找到的核心反例，主要构造和教程示例可以由同一套规则解释。
