# 参数包 v2：语义契约与审计边界

[English](contract.md) | 简体中文

状态：已接入 0.10.0 开发版，尚未发布；本目录仍是独立语义模型。主教程见 [tutorial.zh-CN.md](tutorial.zh-CN.md)。本文件用于精确定义及寻找反例，不要求初学者先读。

## 1. 数据结构与表示

普通 Ty 沿用现有意义，包括普通类型、普通元组和候选列表。新增/统一的结构是 `Pack(items)`；它只保存直接成员，没有“来自元组还是列表”的来源标记。`Choice(items)` 表示候选，`Decl(params,body)` 表示现有 fresh 声明载体的模型对应物。这些记号不属于用户语法。

`*X`：穿过声明载体处理其主体；X 已是 Pack 则返回同一个 Pack；X 为普通元组或候选列表则取直接成员；其他完整类型作为一个成员。包不会递归打开普通类型。原始指针 `*const`/`*mut` 先于这个规则识别。

本模型覆盖的普通 Ty 与包表达式使用逗号区分单项容器。`(X)` 透明、`(X,)` 元组；`[X]` 切片、`[X,]` 候选。0.10.0 有意取消旧的 lone-splat 升格特例。现有 `(@0..)` 等位置引用元语法有自己的特殊分组契约，本模型没有重定义或实现它们；不能据此宣称这些旧写法被删除。空 `[]` 是**空候选列表**：星号打开它是空包（`*[]`），给它长度就是生成器（`*[].N`）；独立解析器已按此实现。切片与数组直接写 `[T]` / `[T; N]`。

`Pack(Pack(A,B),Pack(C,D))` 与 `Pack(A,B,C,D)` 在最终拼接后可能相同，但继续应用时不同；不允许把“最终 Rust 类型相同”当成任意上下文中的 DSL 等价。

## 2. 两个递归操作

`Apply(L,R)` 是通常的 apply；`MapTask(L,row)` 是同一次映射内部保持整行输入的辅助操作，不是新语法或可观察变量。

Apply 的顺序：

1. 传递两边已有声明载体，左侧声明在前，按 fresh 身份合并重复引用。
2. 右侧外露候选先分派，再分派左侧外露候选；每支重新执行 Apply。顺序不得交换，否则 fresh 生成次数可能改变。
3. 右侧为范围时，对每个数值执行 Apply；空范围报错。
4. 普通元组或 Pack 遇数值，按第 3 节生成。
5. 左侧为 Pack：右侧若也是 Pack，则只枚举其直接行，对每行执行 MapTask，结果保留在新的外包；否则对右侧整体执行 MapTask。
6. 其他情况执行该普通 Ty 既有的 apply。`self` 返回完整右值，普通构造器追加右值为实参/槽；右包在其槽内待收纳，不重新参与外层映射。

MapTask 的顺序：

1. 同样传递声明载体。
2. 右侧/左侧外露候选依次分派；每支**继续 MapTask**，不能退回 Apply 而重新拆行。
3. 左侧为 Pack 时，遍历其直接成员，分别继续 MapTask，保留左包结构。
4. 左侧是普通叶时，调用普通 Apply，把 row 整体交给它。

重要修正：v1 在第 2 步遗漏左候选。因此 `*[[*F,*G],] *[*[A, B],]` 会绕路把一行再次拆开。v2 得到两个候选 `F<A,B>`、`G<A,B>`。此修正不增加标记种类。

## 3. 生成器与复制

普通元组 `.N`：保持现有的直接槽位规则；空元组生成 N 个 fresh 参数；一个槽复制 N 次；多个槽做 N 次笛卡尔选择。**不得先展开槽里的 Pack 或候选**。

Pack `.N`：数值操作是一个明确的包消费者，先拼接自身嵌套 Pack 层及其声明载体；普通候选保留。之后按同样的空/单/多成员规则生成，每个输出仍是 Pack。包的空/非空含义以这次消费后的成员表为准。

因此：

```text
(*[A, B],).2  → 一个 (A,B,A,B) 目标
(*[],).2     → ()，不产生 fresh
*[*[],].2    → 空包求幂，产生两个 fresh
```

范围产生候选族，声明属于各个生成分支。`.0` 不分配 fresh 组号。对已经生成的参数作复制，复制的是同一身份的引用，不再次创建参数；只有实际执行生成规则才分配身份。

`self E` 对已形成的结构值保持恒等；不对任意待用的数字/范围操作数承诺代数交换律。数字/范围不是可以作为普通 Rust 类型随意放置的值。

## 4. 物化与宿主

最后才把结构表达式物化为普通类型：

- Choice：保留候选分支；并列槽的选择构成笛卡尔组合。
- Pack：递归拼接包层，声明同时合并；不打开普通元组或普通类型的内部结构作为外层成员。
- 普通元组/泛型实参表/函数参数表：收纳物化后的多个槽。
- 引用目标、指针目标、切片/数组元素、函数返回位置：每个分支恰有一个类型；零项或多项报单槽诊断。
- 裸目标包：逐成员产生目标；不自动去重。

直接 `F<...>` 构造实参宿主。物化 `F<*[A, B],*[C, D]>` 得到 `F<A,B,C,D>`，不能把这些已经收纳的实参重放成新的 apply 链。这关闭了旧审计指出的“等价只在特定阶段成立”的漏洞。

实现可延迟真正拼接，但不可跨越上述普通类型边界重新映射。原始中间结构与物化后 Rust 类型不是自由可互换的表达式。

空包 `Pack()` 与一行空包 `Pack(Pack())` 必须保留差别。前者交给 `*F` 产生零项，后者产生一个无实参 F。

## 5. 候选与声明的作用范围

只在当前操作位置处理外露候选，不扫描普通类型内部做全局预选择。因此 `([A,B],).2` 保持四种组合；隐藏候选的复制可以独立展开。若需让同一次输入整体选定，把候选写到该次应用的外层，如 `[(A,),(B,)]`。

MapTask 内部对当前外露输入候选先分派，再把选出的同一输入交给各个构造器。它不允许左侧候选选出 Pack 后重新拆当前行。

fresh 声明不是从最终出现的名字反推得到。进入输出的 Decl 载体必须完整保留；同一身份重复引用只声明一次。

有意区分两种情况：

- `(*Map *[].2 *[].0,)`：携带出的两个声明仍在，目标是 ()，Rust 报 E0207。
- `(*(().2),).0`：普通元组的整个模板槽重复零次，该槽内的声明载体没有进入结果，输出是无声明的 ()。

这不是“删除没用到的参数”，而是按结构规则判断哪些声明载体进入了结果。显式参数、约束及关联类型投影的完整判定仍交给既有实现/Rust；本模型没有声称解决一般 E0207。

## 6. 确认过的能力与边界

已覆盖：逐位置包装；同位置多次引用同一 fresh；每位置普通元组或 Pair；长度族；整体/逐位置构造器选择；两维与三维笛卡尔组合；同样的包结果按平坦成员或普通行元组收纳。

未新增：zip、索引、lambda、任意带孔构造模板、变量绑定、跨槽自动约束。`Vec.Box` 是已构造类型，不是等待一个 T 的 `Vec<Box<T>>` 函数。

两个正长度范围保留行时，本轮六个 Map 矩阵 impl 可编译；对应扁平族实际 E0119。该例证明保行有价值，不是任意组合都满足 coherence 的证明。

声明块只能接收合法参数声明；包不将构造后的普通类型变成参数名。where、impl 模板、body、指令参数保持各自现有语法域。本次没有把 `*` 扩进这些语法域，也没有宣称所有声明/约束载体都已完成实现验证。

## 7. 模型验证与生产验证边界

本目录模型仅使用 Python 标准库，不依赖公开宏。统一入口是 `python tests/pack_model/run.py`，所有生成物写入 `target/pack-model/`。源码文本解析的支持集合可从 syntax.py 直接查看；不支持的字符会明确拒绝。

覆盖普通名字/路径、直接泛型实参、元组/候选、星、空格/点号、数值/范围、切片/固定数组、引用/原始指针、函数类型宿主。部分旧的前缀 apply（例如 `fn.(A,B)`）没有在独立解析器重写；模型拒绝它们不意味着 DSL 应删除这些能力。

审计层次：

1. 手写预期输出的教学用例与回归用例；生成器、零轴和声明独立断言。
2. 有限小结构穷举：恒等、星幂等、源表示回写、物化、声明来源、映射任务延续等。
3. Rust 验证：每个输出族使用同一个 trait，按模型原始声明编译；另锁定 E0119/E0207 负例。
4. 中英教程中的带标记代码与预期输出自动对照。

解析深度、语义递归、输出规模和工作量有独立上限。它们用于保证模型运行可控；生产实现另有项目自身的规模与质量检查。

完整 Ty 分派、声明/约束绑定、属性和指令载体、生命周期/const 泛型、卫生性和跨度、原始指针与前缀的完整词法、展开规模及真实消费项目，仍须通过生产宏的测试另行验证。模型运行不执行这些测试；接入状态不扩大独立解析器的覆盖范围。

本模型内找到的反例已经变成回归检查；有限域中未见未关闭的反例。这个结论不等于“已证明无任何漏洞”，也不等于已具备发布条件。
